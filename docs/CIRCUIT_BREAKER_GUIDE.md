## 1. 전체 아키텍처

```
┌──────────────┐     ┌──────────────────────────────────────┐     ┌──────────────┐
│              │     │         SimpleCircuitBreaker          │     │              │
│   Service    │────►│                                      │────►│  외부 서비스   │
│   (호출자)    │     │  ┌────────┐ ┌──────┐ ┌───────────┐  │     │  (API, DB 등) │
│              │◄────│  │ CLOSED │ │ OPEN │ │ HALF_OPEN │  │     │              │
│              │     │  └────────┘ └──────┘ └───────────┘  │     │              │
│              │     │       │          │                    │     │              │
│              │     │       │     ┌────┴────┐              │     │              │
│              │     │       │     │ Fallback │              │     │              │
│              │     │       │     └─────────┘              │     │              │
└──────────────┘     └──────────────────────────────────────┘     └──────────────┘
```

서킷 브레이커는 호출자와 외부 서비스 사이에 위치하여 요청을 중계하거나 차단한다.

## 2. 상태 전이

```
                    연속 실패 5회 (FAILURE_THRESHOLD)
           ┌─────────────────────────────────────────────┐
           │                                             ▼
     ┌───────────┐                                ┌───────────┐
     │           │                                │           │
     │  CLOSED   │                                │   OPEN    │
     │  (정상)    │                                │  (차단)    │
     │           │                                │           │
     │ 모든 요청  │                                │ 모든 요청  │
     │ 통과      │                                │ 즉시 거부  │
     │           │                                │ (폴백 실행) │
     └───────────┘                                └───────────┘
           ▲                                           │
           │                                    30초 경과
           │                                  (TIMEOUT_SECONDS)
           │                                           │
           │          ┌───────────────┐                ▼
           │          │               │          ┌───────────┐
           │          │   시험 요청    │          │           │
           └──────────│   성공        │◄─────────│ HALF_OPEN │
                      │               │          │  (시험)    │
                      └───────────────┘          │           │
                                                 │ 제한된 요청 │
                            시험 요청 실패         │ 허용       │
                       ┌─────────────────────────│           │
                       │                         └───────────┘
                       │                               ▲
                       └───── OPEN으로 복귀 ────────────┘
```

| 상태 | 동작 | 전환 조건 |
|------|------|----------|
| `CLOSED` | 모든 요청 통과, 실패 카운트 | 연속 실패 5회 → OPEN |
| `OPEN` | 모든 요청 즉시 거부 (폴백 실행) | 30초 경과 → HALF_OPEN |
| `HALF_OPEN` | 제한된 요청 허용하여 복구 확인 | 성공 → CLOSED / 실패 → OPEN |

## 3. `execute()` 메서드 흐름

`SimpleCircuitBreaker.java` — `execute(action, fallback)` 메서드

```
execute(action, fallback) 호출
    │
    ▼
┌──────────────────┐
│ 현재 상태 확인    │
└──────────────────┘
    │
    ├── OPEN ──────────────────────────────────────────────────────┐
    │                                                              │
    │   ┌──────────────────────┐                                   │
    │   │ timeout 경과 여부?    │                                   │
    │   └──────────────────────┘                                   │
    │       │              │                                       │
    │     경과           미경과                                     │
    │       │              │                                       │
    │       ▼              ▼                                       │
    │   HALF_OPEN      fallback.get() 반환                         │
    │   으로 전환       (외부 호출 없이 즉시 실패)                    │
    │       │                                                      │
    │       ▼                                                      │
    ├── CLOSED / HALF_OPEN                                         │
    │                                                              │
    │   ┌──────────────────────┐                                   │
    │   │  action.get() 실행    │                                   │
    │   │  (실제 외부 호출)      │                                   │
    │   └──────────────────────┘                                   │
    │       │              │                                       │
    │     성공           예외 발생                                   │
    │       │              │                                       │
    │       ▼              ▼                                       │
    │   onSuccess()    onFailure()                                 │
    │       │              │                                       │
    │       │              ├── HALF_OPEN → 즉시 OPEN               │
    │       │              │                                       │
    │       │              └── CLOSED + count >= 5 → OPEN          │
    │       │                                                      │
    │       ├── HALF_OPEN → CLOSED (복구 확인)                      │
    │       │                                                      │
    │       └── failureCount = 0 (초기화)                           │
    │                                                              │
    ▼                                                              ▼
  result 반환                                              fallback 반환
```

## 4. 연쇄 장애 방지 시나리오

서킷 브레이커가 없을 때 vs 있을 때:

```
── 서킷 브레이커 없음 ──

Service A ──→ Service B ──→ Service C (장애)
    │              │              ✗ 응답 없음
    │              │◄── 30초 대기 ──┘
    │◄── 30초 대기 ─┘
    ✗ 스레드 고갈
    ✗ A도 장애 전파 (Cascading Failure)

── 서킷 브레이커 있음 ──

Service A ──→ Service B ──→ [CircuitBreaker] ──✗──→ Service C (장애)
    │              │              │
    │              │              │ OPEN 상태 (5회 실패 후)
    │              │              │ → 즉시 fallback 반환
    │              │◄── 즉시 응답 ─┘
    │◄── 즉시 응답 ─┘
    ✓ 스레드 보호
    ✓ 장애 격리 (Fault Isolation)
```

## 5. 스레드 안전성 구현

```
┌─────────────────────────────────────────────────────┐
│  동시 요청 처리 (멀티 스레드 환경)                      │
│                                                     │
│  Thread-1 ──→ execute() ──→ AtomicReference<State>  │
│  Thread-2 ──→ execute() ──→   (CAS 기반 상태 전환)   │
│  Thread-3 ──→ execute() ──→ AtomicInteger            │
│                               (원자적 카운트 증감)    │
│                                                     │
│  ┌──────────────────┬────────────────────────────┐  │
│  │ 필드              │ 스레드 안전 보장 방식        │  │
│  ├──────────────────┼────────────────────────────┤  │
│  │ state             │ AtomicReference (CAS)      │  │
│  │ failureCount      │ AtomicInteger (CAS)        │  │
│  │ lastFailureTime   │ volatile (가시성 보장)      │  │
│  └──────────────────┴────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

## 6. 핵심 설정값

| 설정 | 값 | 설명 | 튜닝 가이드 |
|------|----|------|-----------|
| `FAILURE_THRESHOLD` | 5 | OPEN 전환 연속 실패 횟수 | 너무 작으면 일시적 오류에도 차단, 너무 크면 장애 전파 |
| `TIMEOUT_SECONDS` | 30 | OPEN → HALF_OPEN 대기 시간 | 외부 서비스 복구 예상 시간에 맞춰 설정 |

## 7. 실무 라이브러리 비교

| 항목 | 수동 구현 (이 프로젝트) | Resilience4j | Hystrix |
|------|----------------------|-------------|---------|
| 상태 관리 | AtomicReference | 내장 상태 머신 | 내장 상태 머신 |
| 메트릭 | 직접 구현 | Micrometer 연동 | Actuator 연동 |
| 슬라이딩 윈도우 | 미지원 (연속 실패만) | 카운트/시간 기반 | 시간 기반 |
| 스레드 격리 | 미지원 | Bulkhead | ThreadPool/Semaphore |
| 유지 상태 | 활발 | **권장** | 유지보수 종료 |
